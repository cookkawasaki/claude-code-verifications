# 〔テーマ〕検証キット

〔何が起きるかを1〜2文。例: 会話が長くなると、Claude Code は古いやり取りを要約に置き換えます。〕このキットでは、〔確かめること〕を、公式ドキュメントの記述どおりか手元で確かめます。

- 参照ドキュメント: 〔URL（節まで）〕
- 所要時間: 〔N〕分ほど（〔N〕つの検証。それぞれ新しいセッションで行います）
- 必要なもの: Claude Code、git、ターミナル（macOS または Linux）
- 少しですがトークンを使います

検証の結果と、そこから分かった Claude Code の使い方の注意点は、こちらにまとめています: 〔[ページ名](ページの URL)。公開前は「まとめページは準備中です」〕

| 検証 | 確かめること |
|---|---|
| 1 | 〔各検証の見出しと同じ文。観察できる結果を、はい／いいえで問う〕 |

## はじめに読むこと

### Claude に任せず、人が手で進める

「README どおりに検証して」と Claude に頼んでもできません。clone も README を読むのも人が行い、Claude には手順にある文だけを入力してください。README は Claude に読ませないでください。

<details>
<summary>理由</summary>

- 〔人にしかできない操作。例: `/compact`（要約）やセッションの起動し直しは、人にしかできません。〕
- 記録する〔`Read ...` などの行〕はターミナルの表示で、Claude 自身には見えません。
- この README には合言葉や予想される結果が書いてあります。Claude が読むと答えを先に知ってしまい、検証になりません。

</details>

### 表記の約束

| 表記 | 意味 |
|---|---|
| **ターミナル:** | ターミナルで打つコマンド |
| **Claude に入力:** | Claude Code の入力欄に打つもの。かぎかっこの中の文は、そのまま入力する |
| **見る:** | 画面で確かめること |
| **記録【1A】** | 結果テンプレートの、同じ見出しの欄に書く |

### 言葉の意味

- **Read ツール**: Claude がファイルを読むときの標準の道具。`cat` コマンドなど別の方法で読むと、扱いが変わることがあります。そのため手順では「Read ツールで」と指定しています。
- 〔このテーマの言葉。例: **要約**: 会話を短くまとめて置き換えること。〕

## 準備（最初に1回だけ）

1. **ターミナル:** 次を打ちます。

   ```bash
   git clone https://github.com/cookkawasaki/claude-code-verifications
   cd claude-code-verifications/topics/〔テーマ名〕
   ```

   すでに clone してあれば、`git pull` してから `topics/〔テーマ名〕` に移動します。

2. `result-template.txt` の中身を、メモアプリやエディタにコピーします。結果はそこに書いていきます（リポジトリの中には保存しないでください）。日付と OS を、記録【環境】に書きます。
3. **ターミナル:** `claude --version` → 記録【環境】
4. **ターミナル:** `ls ~/.claude/CLAUDE.md` → ファイル名が出たら「ある」、`No such file or directory` と出たら「ない」 → 記録【環境】
   - 自分で作った覚えがなくても、あることがあります。必ず打って確かめてください。
   - 会社が配っている Claude Code の設定があるかも、分かる範囲で記録【環境】に書きます。分からなければ「分からない」で構いません。
5. **ターミナル:** `ls ../../.claude` → `No such file or directory` と出れば「ない」 → 記録【環境】
   - 何か出たら、前に許可を「次から聞かない」にした名残です。下の「困ったときの操作」に従って消してから進みます。
6. **ターミナル:** `claude` → **Claude に入力:** `/memory` を打ち、開いたメモに前の検証の名残（合言葉など）があれば消して保存します → 記録【環境】 → **Claude に入力:** `/exit`
7. モデルは Sonnet を勧めます（Claude Code の中で `/model` を打って切り替え）。エフォート（考える量）の設定があれば、低め〜標準で十分です。 → 記録【環境】
8. 初めて `claude` を起動すると、このフォルダを信頼するか聞かれます。許可してください〔理由があれば。例: 検証2のフックを動かすため〕。

## 共通の約束

- **`claude` は、このフォルダ（`topics/〔テーマ名〕`）で起動します。** ほかのフォルダで起動すると、このテーマの設定が最初から読み込まれず、結果が変わります。
- **検証ごとに Claude Code を起動し直します。** 終わったら `/exit` で閉じ、次の検証は `claude` から始めます。前の検証の内容が混ざらないようにするためです。
- **許可を聞かれたら「Yes」（今回だけ）を選びます。** 「次から聞かない（don't ask again）」は選びません。
- 検証の合間に、次の2つを確かめます。
  - **ターミナル:** `git status .` を打ち、`nothing to commit, working tree clean` と出るか。変更されたファイルが出たら、`git restore .` で戻してから次へ進みます。
  - 次の検証を始めたら、最初に **Claude に入力:** `/memory` を打ち、前の検証の名残（合言葉など）があれば消して保存します。

## 困ったときの操作

- **違うフォルダで `claude` を起動してしまった:** `/exit` で閉じ、`cd` で `topics/〔テーマ名〕` に移動して、その検証を最初からやり直します。
- **許可を「次から聞かない」にしてしまった:** その検証を終えたら、**ターミナル:** `rm ../../.claude/settings.local.json` で消します。消したことをテンプレートの「気づいたこと」に書きます。
- **Claude が手順にないファイル（README など）を読んだ:** そのまま続け、読んだファイルの名前を、その検証の【1Z】などの欄に書きます。
- **前の検証の答えを、Claude が最初から知っていた:** `/memory` で名残を消し、その検証を `claude` の起動からやり直します。
- **手順の途中で分からなくなった:** `/exit` で閉じ、`git restore .` で戻して、その検証を最初からやり直します。

## 終わったら

1. 予想と違った点を、テンプレートの「気づいたこと」に書きます。
2. 誰かに見せる前に、**社内のフォルダ名やプロジェクト名、ユーザー名、PC 名が混ざっていないか**確認してください。
3. 結果を共有してくれる場合は、埋めたテンプレートを、このキットを教えてくれた人に送ってください（任意です）。
4. **ターミナル:** 次を打つと元の状態に戻ります〔touch を使うなら: （`touch` で変えた更新日時は戻りませんが、検証には影響しません）〕。

   ```bash
   git restore .
   git status .   # 「nothing to commit, working tree clean」と出れば元どおり
   ```
