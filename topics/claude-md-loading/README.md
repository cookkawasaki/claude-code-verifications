# CLAUDE.md が複数あるときの読まれ方 検証キット

Claude Code は、`CLAUDE.md` などの指示書を自動で読み込み、会話の最初から指示として使います。このキットでは、指示書をいくつかのフォルダに置いたとき、どれが・どの順で・いつ読み込まれるかを、公式ドキュメントの記述どおりか手元で確かめます。

- 参照ドキュメント: https://code.claude.com/docs/en/memory#how-claude-md-files-load
- 所要時間: 20分ほど（2つの検証。それぞれ新しいセッションで行います）
- 必要なもの: Claude Code、git、ターミナル（macOS または Linux）
- 少しですがトークンを使います

検証の結果と、そこから分かった Claude Code の使い方の注意点は、こちらにまとめています: まとめページは準備中です

| 検証 | 確かめること |
|---|---|
| 1 | app で起動すると、上のフォルダの分も含めて5つの指示書の言葉が、上から順にそろって答えられるか |
| 2 | テーマのフォルダで起動すると、サブフォルダの指示書の言葉は、Claude がそのフォルダのファイルを開くまで答えられないか |

## はじめに読むこと

### Claude に任せず、人が手で進める

「README どおりに検証して」と Claude に頼んでもできません。clone も README を読むのも人が行い、Claude には手順にある文だけを入力してください。README は Claude に読ませないでください。

<details>
<summary>理由</summary>

- 起動するフォルダを変えること（`cd app` してから `claude`）と、`/context all`（読み込まれた指示書の一覧）は、人にしかできません。
- 記録する `Loaded ...` の行はターミナルの表示で、Claude 自身には見えません。
- この README には、指示書の言葉や予想される結果が書いてあります。Claude が読むと答えを先に知ってしまい、検証になりません。

</details>

### 表記の約束

| 表記 | 意味 |
|---|---|
| **ターミナル:** | ターミナルで打つコマンド |
| **Claude に入力:** | Claude Code の入力欄に打つもの。かぎかっこの中の文は、そのまま入力する |
| **見る:** | 画面で確かめること |
| **記録【1A】** | 結果テンプレートの、同じ見出しの欄に書く |

### 言葉の意味

- **Read ツール**: Claude がファイルを読むときの標準の道具。`cat` コマンドなど別の方法で読むと、扱いが変わることがあります。そのため手順では「Read ツールで」と指定しています。
- **指示書**: `CLAUDE.md`、`CLAUDE.local.md`、`.claude/CLAUDE.md` をまとめた呼び方です。1つを指すときはファイル名で書きます。
- **読み込まれる**: 指示書が、Claude Code によって自動で Claude に渡されること。Claude が Read ツールでファイルを開くこと（「読む」）とは書き分けています。
- **起動したフォルダ**: `claude` を打ったときにいたフォルダ。**サブフォルダ**はその下のフォルダ、**上のフォルダ**はその上のフォルダです。

## 準備（最初に1回だけ）

1. **ターミナル:** 次を打ちます。

   ```bash
   git clone https://github.com/cookkawasaki/claude-code-verifications
   cd claude-code-verifications/topics/claude-md-loading
   ```

   すでに clone してあれば、`git pull` してから `topics/claude-md-loading` に移動します。

2. `result-template.txt` の中身を、メモアプリやエディタにコピーします。結果はそこに書いていきます（リポジトリの中には保存しないでください）。日付と OS を、記録【環境】に書きます。
3. **ターミナル:** `claude --version` → 記録【環境】
4. **ターミナル:** `ls ~/.claude/CLAUDE.md` → ファイル名が出たら「ある」、`No such file or directory` と出たら「ない」 → 記録【環境】
   - 自分で作った覚えがなくても、あることがあります。必ず打って確かめてください。
   - 会社が配っている Claude Code の設定があるかも、分かる範囲で記録【環境】に書きます。分からなければ「分からない」で構いません。
5. **ターミナル:** `ls ../../.claude` → `No such file or directory` と出れば「ない」 → 記録【環境】
   - 何か出たら、前に許可を「次から聞かない」にした名残です。下の「困ったときの操作」に従って消してから進みます。
6. **ターミナル:** `claude` → 次の3つを確かめてから **Claude に入力:** `/exit`
   - **Claude に入力:** `/memory` を打ち、開いたメモに前の検証の名残（合言葉など）があれば消して保存します → 記録【環境】
   - **Claude に入力:** `/config` を打ち、`Project instructions` の項目の値を見ます。項目が無ければ「無い」 → 記録【環境】
   - **Claude に入力:** `/permissions` を打ち、拒否（Deny）の欄に `Read` で始まるルールがあるか見ます → 記録【環境】
7. Claude Code をエディタ（VS Code など）の中で使っているか、エディタとつないでいるか → 記録【環境】
   - つないでいるなら、検証の間はこのキットのファイルをエディタで開かないでください（下の「共通の約束」）。
8. モデルは Sonnet を勧めます（Claude Code の中で `/model` を打って切り替え）。エフォート（考える量）の設定があれば、低め〜標準で十分です。 → 記録【環境】
9. 初めて `claude` を起動すると、このフォルダを信頼するか聞かれます。許可してください（許可しないと、このフォルダの指示書が読み込まれないことがあるため）。検証1で `app` で起動したときに聞かれたら、そこでも許可します。

## 共通の約束

- **`claude` は、このフォルダ（`topics/claude-md-loading`）で起動します。ただし検証1だけは、その下の `app` で起動します。** 起動するフォルダによって読み込まれる指示書が変わるので、手順にあるフォルダ以外で起動すると、結果が変わります。
- **検証ごとに Claude Code を起動し直します。** 終わったら `/exit` で閉じ、次の検証は `claude` から始めます。前の検証の内容が混ざらないようにするためです。
- **許可を聞かれたら「Yes」（今回だけ）を選びます。** 「次から聞かない（don't ask again）」は選びません。
- **ファイルを `@` で指しません。** ファイルを開いてほしいときは、手順の文のとおりに頼みます。`@` で指すと、Read ツールを通らずに中身が渡り、結果が変わります。
- **検証の間は、このキットのファイルをエディタで開いたままにしません。** エディタと Claude Code をつないでいると、開いているファイルのフォルダの指示書が読み込まれることがあります。
- **Esc を2回押して会話を巻き戻したら、その検証を `claude` の起動からやり直します。** 巻き戻すと、どの指示書を読み込んだかの記録も一緒に消え、結果が変わります。
- 検証の合間に、次の2つを確かめます。
  - **ターミナル:** `git status .` を打ち、`nothing to commit, working tree clean` と出るか。変更されたファイルが出たら、`git restore .` で戻してから次へ進みます。
  - 次の検証を始めたら、最初に **Claude に入力:** `/memory` を打ち、前の検証の名残（合言葉など）があれば消して保存します。

### デスクトップアプリの Code タブで試すとき

- `cd` と `claude` の代わりに、手順にあるフォルダ（検証1は `app`、検証2は `topics/claude-md-loading`）を選んで、新しいセッションを始めます。worktree は使いません。
- `Loaded` の行が出ないことがあります。そのときは、その欄に「出なかった」と書いて先へ進みます。

## 検証1　app で起動すると、上のフォルダの分も含めて5つの指示書の言葉が、上から順にそろって答えられるか

**ねらい:** このフォルダと、その下の `app` に、次の5つの指示書を置いてあります。どれも検証用のダミーで、中身は「この指示書の言葉は「△△」」の1行だけです。言葉には場所を表す語を入れていません（Claude が場所から並びを推し量って答えないようにするため）。`CLAUDE.local.md` はふつうは自分だけのもので commit しませんが、ここでは誰でも同じ状態で試せるよう、commit してあります。

- `CLAUDE.md`（このフォルダ。`app` から見ると上のフォルダ）
- `CLAUDE.local.md`（このフォルダ）
- `app/CLAUDE.md`
- `app/.claude/CLAUDE.md`
- `app/CLAUDE.local.md`

`app` で起動し、上のフォルダの2つも読み込まれるか、5つが上書きし合わずに全部入るか、どの順に並ぶかを、表（`/context all`）と、Claude に渡った文の両方で見ます。名前の順（アルファベット順）に並べると `.claude/CLAUDE.md` → `CLAUDE.local.md` → `CLAUDE.md` になるので、名前の順に並んでいるだけなら見分けられます。

1. **ターミナル:** `cd app`
2. **ターミナル:** `claude`
   - **見る:** 起動したとき、指示書が止められた・読めなかったという行が出たか。出たら、そのまま貼る → 記録【1C】
3. **Claude に入力:** `/memory` を打ち、前の検証の名残があれば消して保存します。
4. **Claude に入力:** `/context all`
   - **見る:** `Memory files` の表を、そのまま貼る → 記録【1A】
5. **Claude に入力:** 「ファイルを読まずに、指示書の見出しの行（Contents of で始まる行）を上から順にそのまま書き写し、それぞれの言葉を添えてください。」
   - **見る:** 答えを、そのまま貼る → 記録【1B】
6. **Claude に入力:** `/exit`
   - 手順以外に Claude がファイルを読んでいたら、その名前 → 記録【1Z】
7. **ターミナル:** `cd ..`（このフォルダに戻ります）

**予想**（2.1.318 で確認）

- 【1A】`CLAUDE.md` → `CLAUDE.local.md` → `app/CLAUDE.md` → `app/.claude/CLAUDE.md` → `app/CLAUDE.local.md` の順に、5つ並ぶ（`app` の中の3つの順は、ドキュメントには一部しか書かれておらず、2.1.318 で試したときの結果）
  - 個人の `~/.claude/CLAUDE.md` や、このリポジトリより上のフォルダの `CLAUDE.md` があれば、それより前に並びます。それらを除いて見てください。
- 【1B】【1A】と同じ順で、やま → かわ → うみ → そら → もり
- 【1C】出ない

<details>
<summary>予想と違ったとき・なぜそうなるか</summary>

- **【1A】に上の2つ（`CLAUDE.md`、`CLAUDE.local.md`）が無い:** 上のフォルダの指示書が読み込まれていません。ただし【1C】に行が出ていたら、会社の設定や Read の拒否ルール（【環境】の `/permissions`）で止められた可能性があります（`app` で起動すると、このフォルダは作業フォルダの外になるため）。【環境】の `Project instructions` が `claude-md` 以外の値なら、それも書き添えてください。
- **言葉が1つしか出ない:** 指示書が上書きし合っています。ドキュメントの「つながって全部入る」と違います。
- **`app` のものが先に並ぶ:** 並びが逆です。ドキュメントでは、上のフォルダのものが先です。
- **やま → うみ → そら → かわ → もり の順:** `CLAUDE.md` の仲間を全部並べてから `CLAUDE.local.md` を並べています。上のフォルダが先なのは記述どおりで、「同じフォルダの中で `CLAUDE.local.md` が後」の読み方が違います。「気づいたこと」に書いてください。
- **`CLAUDE.local.md` が `CLAUDE.md` より先:** 名前の順に並んでいるだけかもしれません。
- **`app/.claude/CLAUDE.md` が無い:** `.claude/CLAUDE.md` はプロジェクトの指示書として読み込まれていません。
- **【1A】と【1B】で順が違う:** 表の並びと、Claude に渡る並びが違います。両方をそのまま送ってください。
- **【1A】に、表に出るはずのファイルが無く、【1C】にも何も出ない:** 個人や会社の設定で、指示書が外されていることがあります。【環境】の欄と合わせて「気づいたこと」に書いてください。
- **この順になる理由:** ドキュメントでは、起動したフォルダから上へたどって見つけた指示書を、上のフォルダのものから順につなげ、同じフォルダの中では `CLAUDE.local.md` を `CLAUDE.md` のあとに付けると書かれています。`.claude/CLAUDE.md` との前後はドキュメントに無く、2.1.318 の本体の中身では `CLAUDE.md` → `.claude/CLAUDE.md` →（`.claude/rules/` のルール）→ `CLAUDE.local.md` の順です。
- **並びは優先の順ではありません:** 2つの指示書に矛盾する指示があると、Claude はどちらかを決まりなく選ぶことがある、とドキュメントにあります。後ろに並ぶ方が勝つわけではありません。

</details>

## 検証2　テーマのフォルダで起動すると、サブフォルダの指示書の言葉は、Claude がそのフォルダのファイルを開くまで答えられないか

**ねらい:** このフォルダの下の `side`、`sub`、`sub/deep` に、それぞれ検証用のダミーの `CLAUDE.md` と、言葉と関係のない1行だけの `.txt` を置いてあります。このフォルダで起動し、サブフォルダの指示書が、起動したときではなく Claude がそのフォルダのファイルを開いたときに読み込まれるかを、ターミナルの `Loaded` の行と、言葉を聞いたときの答えで見ます。

- `ls`（ファイルの一覧を見るだけ）と `cat`（1つのファイルの中身を出す）で違いがあるかを見ます。
- 深い `sub/deep/c.txt` を先に読み、途中の `sub` の指示書も一緒に読み込まれるかを見ます。そのあと `sub/a.txt` を読み、`sub` の指示書が2回目は読み込まれないかを見ます。
- 最後に、サブフォルダの指示書が `/context all` の表に出るかを見ます。

`ls` と `cat` は、人が `!` を付けて打たず、手順の文で Claude に頼みます。

1. **ターミナル:** `claude`（このフォルダ `topics/claude-md-loading` で起動します）
2. **Claude に入力:** `/memory` を打ち、前の検証の名残があれば消して保存します。
3. **Claude に入力:** 「ファイルを読まずに、いま渡されている指示書の言葉を、渡されている順にすべて答えてください。言葉だけを並べてください。」
   - **見る:** 答えを、そのまま貼る → 記録【2A】
4. **Claude に入力:** 「Bash で ls side を実行して、結果を見せるだけにして、ほかのファイルは開かないでください。」
   - **見る:** `Loaded` で始まる行が出たか → 記録【2B】
5. **Claude に入力:** 「ファイルを読まずに、いま渡されている指示書の言葉を、渡されている順にすべて答えてください。言葉だけを並べてください。」
   - **見る:** 答えを、そのまま貼る → 記録【2B】
6. **Claude に入力:** 「Bash で cat side/s.txt を、記号を足さずにそのまま実行してください。」
   - **見る:** `Bash(` で始まる行と、`Loaded` で始まる行を、そのまま貼る → 記録【2C】
   - `Bash(` の行に `|`、`>`、`&&`、`cd` が入っていたら、手順どおりではありません。そのまま貼って先へ進みます。
7. **Claude に入力:** 「Read ツールで sub/deep/c.txt を読んでください。」
   - **見る:** `Loaded` で始まる行を、全部そのまま貼る → 記録【2D】
8. **Claude に入力:** 「Read ツールで sub/a.txt を読んでください。」
   - **見る:** `Loaded` で始まる行が出たか → 記録【2E】
9. **Claude に入力:** 「ファイルを読まずに、いま渡されている指示書の言葉を、渡されている順にすべて答えてください。言葉だけを並べてください。」
   - **見る:** 答えを、そのまま貼る → 記録【2F】
10. **Claude に入力:** `/context all`
    - **見る:** `Memory files` の表を、そのまま貼る → 記録【2G】
11. **Claude に入力:** `/exit`
    - 手順以外に Claude がファイルを読んでいたら、その名前と、どの手順のあとか（とくに、`CLAUDE.md` そのものを開いたか） → 記録【2Z】

**予想**（2.1.318 で確認）

- 【2A】やま → かわ だけ（`app`、`side`、`sub` の言葉は出ない）
- 【2B】`Loaded` の行は出ない。言葉も やま → かわ だけ（ドキュメントに書かれておらず、2.1.318 で試したときの結果）
- 【2C】`Bash(cat side/s.txt)` と、`side/CLAUDE.md` の `Loaded` の行
- 【2D】`sub/CLAUDE.md` と `sub/deep/CLAUDE.md` の、2つの `Loaded` の行（途中のフォルダの分も一緒に読み込まれる。ドキュメントに書かれておらず、2.1.318 で試したときの結果）
- 【2E】出ない（`sub/CLAUDE.md` は【2D】で読み込み済みのため。ドキュメントに書かれておらず、2.1.318 で試したときの結果）
- 【2F】やま → かわ → にじ → ほし → つき
- 【2G】`CLAUDE.md` と `CLAUDE.local.md` の2つだけ。サブフォルダのものは出ない

<details>
<summary>予想と違ったとき・なぜそうなるか</summary>

- **【2A】にサブフォルダの言葉が出る:** 起動したときに読み込まれているか、Claude が手順の前にファイルを開いています。【2Z】を見て、開いていなければ「気づいたこと」に書いてください。
- **【2B】に `Loaded` の行が出る、または言葉が増える:** `ls` でもそのフォルダの指示書が読み込まれています。【2Z】で、`ls` のあとに Claude が `side` のファイルを開いていないかも見てください。
- **【2C】に `Loaded` の行が出ない（ターミナルで）:** `cat` は「読む」に数えられていません。ただし、`Bash(` の行に記号や `cd` が入っていたら、手順どおりではありません。【2Z】で、手順の前に `side/CLAUDE.md` を開いていたら、読み込み済みとして飛ばされています。
- **【2D】が `sub/deep/CLAUDE.md` の1行だけ:** 途中のフォルダの指示書は読み込まれていません。【2F】に「ほし」が無いかも見てください。
- **【2E】に `Loaded` の行が出る:** 同じフォルダの指示書が2回読み込まれています。
- **`Loaded` の行がどこにも出ない（Code タブや、表示が畳まれているとき）:** 【2B】【2E】の「出ない」は判定に使えません。各欄に「出なかった」と書き、言葉の答え（【2B】【2F】）で確かめます。
- **【2G】にサブフォルダの指示書が出る:** ドキュメントの「必要になったときに読み込まれたものは、表に出ない」と違います。
- **こうなる理由:** ドキュメントでは、サブフォルダの指示書は起動したときには読み込まれず、Claude がそのフォルダのファイルを読んだり書いたり編集したりしたときに読み込まれる、と書かれています。1つのファイルを見る `cat` のような Bash も「読む」に数えます。2.1.318 の本体の中身では、記号を含むコマンドやつないだコマンドは数えず、一度読み込んだ指示書は覚えておいて2回目を飛ばします。
- **補足:** 2.1.318 で試したときは、Write でファイルを作ったときにも、サブフォルダの `CLAUDE.md` や `CLAUDE.local.md` が読み込まれました。必要になったときに読み込まれる指示書は、長すぎると始めの部分しか渡されません（ドキュメントの記載。200K のコンテキストで 40,000 文字ほど。数値はバージョンによって変わりえます）。

</details>

## 困ったときの操作

- **違うフォルダで `claude` を起動してしまった:** `/exit` で閉じ、`cd` で手順にあるフォルダ（検証1は `topics/claude-md-loading/app`、検証2は `topics/claude-md-loading`）に移動して、その検証を最初からやり直します。
- **許可を「次から聞かない」にしてしまった:** その検証を終えたら、**ターミナル:** `rm ../../.claude/settings.local.json` で消します（`app` にいるときは `rm ../../../.claude/settings.local.json`）。消したことをテンプレートの「気づいたこと」に書きます。
- **Claude が手順にないファイル（README や指示書など）を読んだ:** そのまま続け、読んだファイルの名前を、その検証の【1Z】【2Z】の欄に書きます。
- **前の検証の答えを、Claude が最初から知っていた:** `/memory` で名残を消し、その検証を `claude` の起動からやり直します。
- **手順の途中で分からなくなった:** `/exit` で閉じ、`git restore .` で戻して、その検証を最初からやり直します。
