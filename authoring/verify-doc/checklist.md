# 確認項目

キットとページを見せる前に、この一覧で見直す。当てはまらない項目は「該当なし」と判断してよいが、飛ばしたことは見直しの報告に書く。
1テーマ目（claude-compact-check とそのページ）の手戻りから作った。テーマを重ねるたびに直す。

## 共通

- [ ] リポジトリに書いていない: 社名、人名、Slack の内容、画面写真、生の結果（貼られた結果そのもの）
- [ ] リポジトリの直下に `CLAUDE.md` と `.claude/` がない（`git ls-files | grep -E '^(CLAUDE\.md|\.claude/)'` が空）
- [ ] 同じ出来事を同じ言葉で書いている。用語のそろえ方は SKILL.md の手順1で決めたものに従う（例:「版」ではなく「バージョン」）
- [ ] 言い切りが強すぎない（「確実です」→「安心です」、「忘れません」→「全部は忘れません」）

## キット

### 構成

- [ ] `templates/topic/` から作り、節の順番が雛形どおり（はじめに読むこと → 準備 → 共通の約束 → 検証 → 困ったときの操作 → 終わったら）
- [ ] 冒頭に、Claude に任せず人が手で進める理由がある。「README を Claude に読ませない」と書いてある
- [ ] 冒頭に表記の凡例（ターミナル: / Claude に入力: / 見る: / 記録【1A】）がある
- [ ] clone のあと `cd claude-code-verifications/topics/<テーマ名>` まで書いてあり、「このフォルダで起動する」が共通の約束にある
- [ ] 準備に、`~/.claude/CLAUDE.md`・会社の設定・`../../.claude`・`/memory` の確かめがある
- [ ] 共通の約束の `git status` / `git restore` に、最後の `.` が付いている（テーマのフォルダの中だけを見るため）
- [ ] 共通の約束に「許可は『Yes』（今回だけ）を選ぶ」がある（「次から聞かない」はリポジトリの直下に書かれ、全テーマで効くため。2.1.318 で確認）

### 各検証

- [ ] 「ねらい → 手順 → 予想 → 折りたたみの補足」の順になっている
- [ ] 人の手が要る手順は、1つの検証で4つ以内が目安（`claude` の起動と `/exit` は数えない）
- [ ] 検証ごとに `claude` の起動から始まり、`/exit` で終わる
- [ ] 各手順の頭に「ターミナル:」「Claude に入力:」「見る:」のどれかが付いている
- [ ] 「見る:」などの2行目は、一段下げた箇条書きになっている（GitHub で前の行にくっつくのを防ぐ）
- [ ] 記録する手順に見出し（記録【1A】）があり、結果テンプレートの行頭に同じ見出しがある。番号で照合させていない（SKILL.md の grep で確かめる）
- [ ] Claude に入力する文は、かぎかっこの中をそのまま打てる。「2と同じ文」のように前を参照させず、毎回全文を書いている
- [ ] ファイルを読ませるときは「Read ツールで」と指定している
- [ ] 手順の途中で判断が要ること（ここで終える、言い直す、など）は手順の側にあり、理由だけが補足にある
- [ ] 紛れを潰している（SKILL.md の「紛れの定番」を一つずつ当てた）。潰した仕掛け（`touch -t` など）の理由が、ねらいに書いてある
- [ ] 予想が実機の結果に合っている。実機で確かめた予想には「（バージョンで試したときの結果）」が付いている
- [ ] 補足に、予想と違ったときの読み方と、テンプレートのどこに何を書くかがある

### 結果テンプレート

- [ ] 書き込み式（「:」のあとに書く。（ ）は案内）
- [ ] 画面の表示を写す欄は「そのまま貼る」になっていて、下に空行がある
- [ ] 【環境】に、日付・バージョン・モデル/エフォート・OS（PC 名は書かない）・個人の CLAUDE.md・会社の設定・`../../.claude`・`/memory` の欄がある
- [ ] 検証ごとに「手順以外に Claude が読んだファイル」の欄がある
- [ ] 結果のまとめ方が、SKILL.md の手順1で決めた受け渡し方法に合っている（依頼者だけが使うなら「送り方」ではなく「まとめ方」）

### 困ったときの操作・終わったら

- [ ] 困ったときの操作に、雛形の項目（違うフォルダで起動した／「次から聞かない」を選んだ／手順外のファイルを読んだ／前の答えを知っていた／分からなくなった）と、このテーマで起きやすいことがある
- [ ] 終わったらに、社内の名前が混ざっていないかの確認と、`git restore .` / `git status .` がある

## ページ

### 構成と見出し

- [ ] 節の順番が雛形どおり（結論 → たとえ → 気をつけること → よくある質問 → 設定を触る人向け → 当てはまる範囲 → 検証で分かったこと → 用語集 → 作り方）
- [ ] 主役は「気をつけること」。検証の経緯は後ろ（当てはまる範囲・検証で分かったこと）にある
- [ ] 冒頭に製品の範囲がある（例: ターミナル版とデスクトップアプリの Code タブ。チャットタブは対象外）
- [ ] 見出しが中身を表している。目次の文字と見出しが一致する（SKILL.md の grep で確かめる）
- [ ] 前半（結論〜よくある質問）は誰でも読める表現。後半（設定を触る人向け、詳しい人向け）はエンジニア向けに厚くしてよい

### たとえと図

- [ ] たとえ話の場面が1つにそろっている（例: ホワイトボード・議事録・付箋・資料・棚）
- [ ] 図に出す要素は、段落でも全部説明している。段落の説明の順番と、図の並び順が同じ
- [ ] ファイル自体が無くなったと読める言い方をしていない（「資料が戻らない」→「資料の中身が読み直されない」）

### 対になるもの

- [ ] 前後や対になるものは、同じ見出し・同じ順番・同じ行数（図の「前／あと」、「なぜ:」と「どうする:」、設定の「前／後」）
- [ ] 設定の変更は「前／後」を並べている
- [ ] 例があれば考えずに済む所に、例がある

### 確からしさ

- [ ] 未確認のことに印がある（「仕組みからの推測」「今回は未検証」「1回だけ確認」）。確かめたことの印は外した
- [ ] 根拠の種類が分かる（ドキュメントの記載／本体の中身／実機で確認）。本体の中身には「バージョンによって変わりうる」の印がある
- [ ] 「検証で分かったこと」の表に、記述どおりか違ったかの印と、確かめた環境（バージョン、製品、OS、回数）がある
- [ ] 手順が使えない場面がないか書いた（例: 自動の要約には一言添えられない）

### 公開の前

- [ ] `<title>` が2〜4語の名前。`meta` のバージョンと日付、フッターのバージョンと日付が同じ
- [ ] リンク（ドキュメント、キット、シリーズ）が正しい。キットのリンクは main のテーマのフォルダを指す
- [ ] 末尾に「このページの作り方」（3行）がある
