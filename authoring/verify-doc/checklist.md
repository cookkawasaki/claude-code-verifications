# 確認項目

キットとページを見せる前に、この一覧で見直す。当てはまらない項目は「該当なし」と判断してよいが、飛ばしたことは見直しの報告に書く。
1テーマ目（claude-compact-check とそのページ）の手戻りから作った。テーマを重ねるたびに直す。

## 共通

- [ ] リポジトリに書いていない: 社名、人名、Slack の内容、画面写真、生の結果（貼られた結果そのもの）。GitHub のアカウント名（clone の URL）は除く
- [ ] リポジトリの直下に `CLAUDE.md` と `.claude/` がない（`git ls-files | grep -E '^(CLAUDE\.md|\.claude/)'` が空）
- [ ] 同じ出来事を同じ言葉で書いている。キットの中、ページの中、キットとページの間でそろえる。基準は `authoring/claims/<テーマ名>.md` の「用語」（例: バージョンの意味では「版」ではなく「バージョン」。「ターミナル版」のような製品名はそのまま）
- [ ] 「必ず」「確実」「〜しません」と言い切る文には、根拠の印（ドキュメントの記載／実機で確認）があるか、和らげる語がある（「確実です」→「安心です」、「忘れません」→「全部は忘れません」）

## キット

### 構成

- [ ] `templates/topic/` から作り、節の順番が雛形どおり（冒頭（参照・所要時間・ページへのリンク・検証の表）→ はじめに読むこと → 準備 → 共通の約束 → 検証 → 困ったときの操作 → 終わったら）
- [ ] 冒頭にページへのリンクがある（公開前は「まとめページは準備中です」）
- [ ] 「はじめに読むこと」に、Claude に任せず人が手で進めることと「README は Claude に読ませないでください」があり、理由が折りたたみにある
- [ ] 「表記の約束」（ターミナル: / Claude に入力: / 見る: / 記録【1A】）がある
- [ ] 「言葉の意味」に、Read ツールとこのテーマの言葉がある
- [ ] clone のあと `cd claude-code-verifications/topics/<テーマ名>` まで書いてあり、「このフォルダで起動する」が共通の約束にある
- [ ] 結果テンプレートは、リポジトリの外（メモアプリなど）にコピーして書く、と準備にある
- [ ] 準備に、`~/.claude/CLAUDE.md`・会社の設定・`../../.claude`・`/memory` の確かめがある
- [ ] 共通の約束に、検証の合間の `git status .`（最後の `.` 付き）と `/memory` の確かめがある
- [ ] 共通の約束に「許可は『Yes』（今回だけ）を選ぶ」がある（「次から聞かない」はリポジトリの直下に書かれ、全テーマで効くため。2.1.318 で確認）

### 各検証

- [ ] 検証の見出しと冒頭の表が同じ文で、観察できる結果を、はい／いいえで問うている。仕組みの専門語を見出しに出していない（「compact 用の SessionStart フック」ではなく「要約の直後に動くフック」）
- [ ] 「ねらい → 手順 → 予想 → 折りたたみの補足」の順になっている
- [ ] 人にしかできない操作（ターミナルのコマンド、`/compact` など）は、1つの検証で4つ以内が目安。Claude に入力する文、見る、`claude` の起動と `/exit` は数えない
- [ ] 起動前の仕込み（`touch` など）と `/exit` のあとの片付けを除き、各検証は `claude` の起動から始まり、`/exit` で終わる
- [ ] 各手順の頭に「ターミナル:」「Claude に入力:」「見る:」のどれかが付いている
- [ ] 「見る:」などの2行目は、一段下げた箇条書きになっている（GitHub で前の行にくっつくのを防ぐ）
- [ ] 記録する手順に見出し（記録【1A】）があり、結果テンプレートの行頭に同じ見出しがある。番号で照合させていない（SKILL.md の grep で確かめる）
- [ ] Claude に入力する文は、かぎかっこの中をそのまま打てる。「2と同じ文」のように前を参照させず、毎回全文を書いている
- [ ] ファイルを読ませるときは「Read ツールで」と指定している
- [ ] 手順の途中で判断が要ること（ここで終える、言い直す、打ち直す、など）は手順の側にあり、理由だけが補足にある
- [ ] キット全体で所要30分ほど・ターミナル1つが目安に収まっている。超えるなら、その理由が SKILL.md の設計に書いてある
- [ ] 試す人のリポジトリの状態（ブランチ、コミット、リポジトリの外のファイル）を変えない。スクリプトは無いか、20行ほどの読めるもので、何をするかが「ねらい」にある
- [ ] 紛れを潰している（SKILL.md の「紛れの定番」を一つずつ当てた）。潰した仕掛け（`touch -t` など）の理由が、ねらいに書いてある
- [ ] 予想が実機の結果に合っている。「予想」の見出しに確かめたバージョンがあり、ドキュメントからは予想できず実機で分かった予想には「（バージョンで試したときの結果）」が付いている
- [ ] 補足に、予想と違ったときの読み方と、テンプレートのどの欄（見出し）に何を書くかがある

### 結果テンプレート

- [ ] 書き込み式（「:」のあとに書く。（ ）は案内）
- [ ] すべての欄に行頭の見出し（【環境】の下の行は除く）があり、README にその欄を書く時点がある
- [ ] 画面の表示を写す欄は「そのまま貼る」になっていて、下に空行がある
- [ ] 【環境】に、日付・バージョン・モデル/エフォート・OS（PC 名は書かない）・個人の CLAUDE.md・会社の設定・`../../.claude`・`/memory` の欄がある
- [ ] 検証ごとに「手順以外に Claude が読んだファイル」の欄（【1Z】など）がある
- [ ] 結果のまとめ方・送り方が、SKILL.md の手順1で決めた受け渡し方法に合っている

### 困ったときの操作・終わったら

- [ ] 困ったときの操作に、雛形の項目（違うフォルダで起動した／「次から聞かない」を選んだ／手順外のファイルを読んだ／前の答えを知っていた／分からなくなった）がある。手順に依ることは、困ったときの操作ではなく手順の中に書いた
- [ ] 終わったらに、社内の名前が混ざっていないかの確認、結果の共有のしかた、`git restore .` / `git status .` がある

## ページ

### 構成と見出し

- [ ] 節の順番が雛形どおり（結論 → たとえ → 気をつけること → よくある質問 → 設定を触る人向け → 当てはまる範囲 → 検証で分かったこと → 用語集 → 作り方）
- [ ] 主役は「気をつけること」。検証の経緯は後ろ（当てはまる範囲・検証で分かったこと）にある
- [ ] 冒頭に製品の範囲がある（例: ターミナル版とデスクトップアプリの Code タブ。チャットタブは対象外）
- [ ] 見出しが中身を表している。目次の文字と見出しが一致する（SKILL.md の grep で確かめる）
- [ ] 前半（結論〜よくある質問）は誰でも読める表現。後半（設定を触る人向け、詳しい人向け）はエンジニア向けに厚くしてよい

### たとえと図

- [ ] たとえ話の場面が1つにそろっている（例: ホワイトボード・議事録・付箋・資料・棚）
- [ ] 図に出す要素は、段落でも全部説明している。段落の説明の順番と、図の並び順が同じ
- [ ] ファイル自体が無くなったと読める言い方をしていない（「資料が戻らない」→「資料の中身が読み直されない」）

### 対になるもの

- [ ] 前後や対になるものは、同じ見出し・同じ数の要素・同じ順番（図の「前／あと」、「なぜ:」と「どうする:」、設定の「前／後」、「誤解」と「実際は」）
- [ ] 既にある書き方を変える設定は「前／後」を並べている（新しく足す設定は「後」だけでよい）
- [ ] 「どうする:」の各項目に、打つ文か書く文の例が1つある

### 確からしさ

- [ ] 印は雛形の冒頭のコメントにある一覧から選んでいる。未確認のことに印があり、確かめたことの未確認の印は外した
- [ ] 根拠の種類が分かる（ドキュメントの記載／本体の中身／実機で確認）。本体の中身から分かった数値には「バージョンによって変わりうる」の印がある
- [ ] 「検証で分かったこと」の表に、記述どおりか違ったかの印がある。確かめた環境（バージョン、製品、OS、回数）は「当てはまる範囲」にある
- [ ] 手順が使えない場面がないか書いた（例: 自動の要約には一言添えられない）

### 公開の前

- [ ] `<title>` が2〜4語の名前。冒頭の「検証: バージョン／年月」の表示と、フッターのバージョンと年月が同じ
- [ ] リンク（ドキュメント、キット、シリーズ）が正しい。キットのリンクは main のテーマのフォルダ（`…/tree/main/topics/<テーマ名>`）を指す
- [ ] 末尾に「このページの作り方」（3行）がある
